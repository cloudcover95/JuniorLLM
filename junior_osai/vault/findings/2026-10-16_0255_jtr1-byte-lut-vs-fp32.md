# JTR1 byte-LUT kernel vs fp32 on exact-ternary weights (numpy)

- Prev: [[2026-10-15_2030_native-bitplane]]
- Answers: [[2026-10-15_2020_lut-kernel-next]] (LUT question; the bit-plane notes [[2026-10-15_2025_bitplane-bench]] and [[2026-10-15_2030_native-bitplane]] skipped LUT)

## Question
The open question from [[2026-10-15_1930_ternary-matvec-baseline]] and [[2026-10-15_2020_lut-kernel-next]]: on weights that are already ternary (trained-ternary stand-in, so no post-hoc error), does a TL-style lookup-table kernel over the i2sd JTR1 pack (Trit Pack's layout, codes 0->0, 1->1, 2->-1, MSB-first) beat fp32 matvec by at least 1.5x at no more than 1% error, using python3 + numpy only? This serves Quant Chief's pair A item for this wave, i2sd userspace.

## Method
- python3, numpy 2.x with scipy-openblas, 8 CPUs, seed 0. No model, no GGUF, no network, nothing bound.
- Layer 4096x4096. Weights are exact ternary T in {-1,0,1} (uniform, p = 1/3 each) times gamma 0.02, so fp32 W = gamma*T is the exact reference.
- Packed with the JTR1 I2_S 2-bit layout from BitNet-mlx `scripts/i2sd_jtr1_pack.py` (round-trip asserted). Bytes per layer = payload + 16 B header (magic, gamma f64, n u32).
- Kernels: fp32 BLAS (resident fp32); fp16 resident (upcast then BLAS); JTR1 dequant per call through a 256x4 byte-to-trits table, then BLAS; JTR1 byte-LUT gather (TL-style): for each group of 4 activations, build a 256-entry table of all signed sums, then gather by pack byte and sum per row (no weight multiplies).
- Warm = same layer every call. Cold = cycle 8 distinct layers (537 MB fp32) so weights stream from DRAM, as per-token decode does.
- Batch 1 (decode) and 32 (prefill). 11 timed repeats after one warm-up; median and min-max ms. Error = ||y - y_fp32|| / ||y_fp32||.
- Script ran twice. The box had about 2 GB free RAM and light load (load average 1.25).

### Command
`python3 /workspace/tbench/bench_lut_20261016.py` (local only). Full script:

```python
import time, numpy as np
rng = np.random.default_rng(0)
DEC = {0: 0, 1: 1, 2: -1, 3: 0}            # JTR1 I2_S codes, MSB-first (Trit Pack scripts/i2sd_jtr1_pack.py)
ENC = np.array([2, 0, 1], np.uint8)        # index t+1 -> code
def pack_jtr1(T):                          # T int8 {-1,0,1}, shape (M,K), K%4==0
    c = ENC[T + 1].reshape(T.shape[0], -1, 4)
    return (c[..., 0] << 6) | (c[..., 1] << 4) | (c[..., 2] << 2) | c[..., 3]
B2T = np.array([[DEC[(b >> s) & 3] for s in (6, 4, 2, 0)] for b in range(256)], np.float32)
def tm(f, r=11):
    f(); ts = []
    for _ in range(r):
        a = time.perf_counter(); f(); ts.append(time.perf_counter() - a)
    ts = np.array(ts) * 1e3; return np.median(ts), ts.min(), ts.max()
M = K = 4096; L = 8
g = np.float32(0.02)
Ts = [rng.integers(-1, 2, (M, K), dtype=np.int8) for _ in range(L)]
Wf = [g * T.astype(np.float32) for T in Ts]
Wh = [w.astype(np.float16) for w in Wf]
Ps = [pack_jtr1(T) for T in Ts]
assert np.array_equal(B2T[Ps[0]].reshape(M, K).astype(np.int8), Ts[0])
cols = np.arange(K // 4)
def lut_mv(P, x):
    Lt = B2T @ x.reshape(-1, 4).T          # (256, K/4)
    return g * Lt[P, cols].sum(1)
def deq_mv(P, X):
    return (g * B2T[P].reshape(M, K)) @ X
res = []
for B in (1, 32):
    X = rng.standard_normal((K, B)).astype(np.float32); x = X[:, 0]
    ref = Wf[0] @ X
    for cache in ("warm", "cold"):
        idx = [0]
        def pick(lst):
            if cache == "warm": return lst[0]
            idx[0] = (idx[0] + 1) % L; return lst[idx[0]]
        impl = {
            "fp32 BLAS": (Wf[0].nbytes, lambda: pick(Wf) @ X, lambda: Wf[0] @ X),
            "fp16 resident (upcast+BLAS)": (Wh[0].nbytes, lambda: pick(Wh).astype(np.float32) @ X, lambda: Wh[0].astype(np.float32) @ X),
            "JTR1 dequant (byte table)+BLAS": (Ps[0].nbytes + 16, lambda: deq_mv(pick(Ps), X), lambda: deq_mv(Ps[0], X)),
        }
        if B == 1:
            impl["JTR1 byte-LUT gather (TL)"] = (Ps[0].nbytes + 16, lambda: lut_mv(pick(Ps), x), lambda: lut_mv(Ps[0], x)[:, None])
        base = None
        for n, (b, f, f0) in impl.items():
            y = f0(); med, lo, hi = tm(f)
            if base is None: base = med
            e = np.linalg.norm(y - ref) / np.linalg.norm(ref)
            res.append((B, cache, n, b, Wf[0].nbytes / b, med, lo, hi, base / med, e))
for r in res:
    print(f"| {r[0]} | {r[1]} | {r[2]} | {r[3]:,} | {r[4]:.1f}x | {r[5]:.2f} | {r[6]:.2f}-{r[7]:.2f} | {r[8]:.2f}x | {r[9]:.1e} |")
```

## Verdict
**Not viable (speed).** The byte-LUT kernel is exact (error 3.5e-7, well under 1%) and is the fastest ternary path in numpy. It is about 3x faster than the previous note's masked add/sub, and about 4.5x faster than dequant-per-call. But it is still about 25-55x slower than fp32 BLAS: 14-16 ms against 0.28-0.59 ms at batch 1, even with weights streamed cold. Its 0.47x in run 1 is not a real result, because it came from the noisy fp32 baseline. Dequant per call (61-69 ms) and fp16 upcast (80-88 ms) are worse at both batch sizes, so batch 32 does not amortise the dequant cost in numpy.

It also loses to the bit-plane path at 4096, where [[2026-10-15_2025_bitplane-bench]] found numpy speed viable only at 512 and [[2026-10-15_2030_native-bitplane]] found a scalar C loop slower than BLAS. Why: numpy's fancy-index gather goes through 4M elements one by one with no SIMD, while OpenBLAS streams fp32 at DRAM bandwidth. The 16x memory win (4.19 MB vs 67.1 MB per layer) holds, but the [[2026-10-15_1930_ternary-matvec-baseline]] note already recorded it, so it is not new. A real speed win still needs a native TL/I2_S kernel (bitnet.cpp style: SIMD shuffle LUT) inside i2sd, not numpy.
